# Демо-экран препроцессинга

```
.venv/Scripts/python.exe -m streamlit run ui/app.py
```

Экран читает то, что оставил прогон. Если данных нет, он это скажет — собрать:

```
.venv/Scripts/python.exe -m tools.run_pipeline --debug
```

Что читается (и ничего не пишется): `data/debug/` — трассировка вход/выход
каждого шага, `data/prepared/main/prepared_events.jsonl` — готовые события,
`data/prepared/run_report.json` — итоги прогона, `data/raw/_meta/` — какие
клиенты ролевые, а какие без краевых случаев.

## Что показывать

Три сюжета, проверенные на этих данных.

**1. Обычная покупка в валюте** — открывается по умолчанию (`C000013`,
`CARD_PURCHASE`, USD). Видно всю цепочку превращений:

| шаг | что происходит |
|---|---|
| 2 | появляется единый `client_id` |
| 3 | локальное время → момент + часовой пояс |
| 6 | появляются тип события и его постоянный номер |
| 8 | из одиннадцати колонок остаются объявленные поля |
| 9 | `840` → `USD` |
| 10 | `3896` тиын → `38.96` |
| 11 | `38.96` USD → `18507.784368` тенге по курсу того дня |
| 14 | `merchant_id` убран — технический идентификатор до модели не доходит |
| 15 | `18507.784368` → `bucket_45` |
| 17 | час 20, день недели 3 |

**2. Испорченное значение.** Клиент `C000005`, запись
`CPX-000005-bad-amount`: в сумме пришло `abc`. На шаге 10 видно
`abc → MISSING` — не ноль.

**3. Сессия в приложении.** Клиент `C000013`, событие `APP_SESSION`. На шаге 7
шестнадцать изменений: отдельные касания экрана превращаются в одно событие с
длительностью и списком экранов. На шаге 15 длительность `3007` секунд
становится `bucket_29`.

## Две вещи, о которых спросят

**Почему после шага 12 идёт 13 «Профиль», а корзины — только на 15?** Порядок
на экране фактический, а не по номерам плана: цепочка исполняется как
2.1…2.11, 2.15, 2.14, 2.13, 2.16, 2.17. Причина в самом регламенте — §24
требует разложить признаки «за всю жизнь» по корзинам, а §37.2 даёт
единственный шаг бакетизации и ставит его раньше расчёта профиля. Профиль
перенесён вперёд, иначе этим полям не досталось бы границ вовсе. На таких шагах
это написано прямо под заголовком.

**Почему у шага 12 нет «было → стало»?** Он выполняется только на расчёте
границ (BUILD), а экран показывает разметку данных (ENCODE). Запись он не
меняет в принципе — только смотрит на неё.
